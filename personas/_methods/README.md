# 方法论叠加层

`personas/` 下的人格可以**叠加**这里的一层教学法约束，得到「某位讲师 + 某种教学法」的组合。
在生成人格时问用户要不要叠加、叠哪一个；**默认不叠加**。

## 怎么用

生成人格时，把选中的那层内容追加到人格 SKILL.md 的「判断与教学法」一节末尾，
并标注来源，例如 `> 教学法约束：《严格推导派》（叠加层，非讲师本人风格）`。

**必须标注**，否则用户会以为这是讲师本人的特点。这也是为什么叠加层单独放一个目录。

## 内置的三层

| 文件 | 教学法 | 什么时候适用 |
|---|---|---|
| `严格推导派.md` | 每一步都要有出处和推导，拒绝"记住结论" | 数学、理论物理、算法证明类课程 |
| `直觉类比派.md` | 先建物理图像和类比，再上形式化 | 入门课、跨专业补课、概念课 |
| `考点导向派.md` | 先讲考什么怎么考，再讲为什么 | 应试、期末冲刺、考研复习 |

## 自己写一层

一个叠加层就是一段可执行的约束，写清三件事：**要求做什么**、**禁止什么**、**遇到冲突时怎么取舍**。
写成 20–40 行的 markdown，放进这个目录即可被选中。

不要把人家的整份人格拷进来——这个目录只放**教学法**，不放具体某个人的风格与内容。
自己的讲师人格请放在 `personas/<讲师名>/`。

## 并列 vs 叠加

- **并列**：`personas/` 里放多个人格（你自己蒸的讲师、别人的大师人格），用户按需把目标人格复制到工作区可发现的 skill 目录后使用。
- **叠加**：一个讲师人格 + 一层教学法约束。适合「我喜欢这个老师讲的内容，但希望他讲得更系统/更应试」。

本项目**不打包任何第三方人格内容**，避免把别人的内容和许可证问题带进仓库。
